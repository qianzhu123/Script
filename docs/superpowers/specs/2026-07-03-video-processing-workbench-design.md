# 视频处理工坊目标文档

日期：2026-07-03

## 背景

当前 `D:\code\myweb\daily\bat` 已经有一组视频处理脚本，主要集中在 `视频处理` 分组：

- `ffmpeg_convert.bat`：视频、音频、图片格式转换。
- `ffmpeg_resize.bat`：视频分辨率调整。
- `ffmpeg_rate.bat`：帧率、视频码率、音频码率调整。
- `ffmpeg_audio.bat`：音频抽取、音量、音频变速、音频格式转换。
- `VideoSpeedExport.bat` + `ps1/VideoSpeedExport.ps1`：按倍速、目标时长、时间范围导出。
- `remove_subtitle.bat` + `ps1/remove_subtitle.ps1`：软字幕移除、裁剪字幕区、delogo 模糊遮盖。
- `video_dubbing.bat` + `ps1/video_dubbing.ps1`：Edge-TTS 配音、字幕生成、音轨混合。

这些脚本的问题不是能力缺失，而是交互形态分散：每个脚本都有自己的命令行菜单，用户需要记住入口、拖入文件、逐项输入参数，无法在一个界面里组合多步处理，也缺少统一预览、任务队列、参数复用和输出管理。

## 目标

创建一个本地视频处理项目，让用户拖入一个视频后，在界面中调整参数，生成最终视频。目标不是简单包一层 BAT 菜单，而是把现有 ffmpeg 能力整理成可组合、可预览、可复用的处理流水线。

用户首次可用目标：

1. 拖入视频或选择本地文件。
2. 自动读取视频信息：时长、分辨率、帧率、码率、音视频流、字幕流。
3. 在一个界面中配置常用视频、音频、字幕、导出参数。
4. 生成 ffmpeg 命令预览，并能一键运行。
5. 实时查看进度、日志、预计输出路径。
6. 输出文件不覆盖原文件，默认写到源文件同目录或项目 `output/video-workbench`。
7. 保存常用参数为预设。

## 非目标

- 第一阶段不做复杂时间线剪辑器，不追求 Premiere/剪映级别体验。
- 第一阶段不做多轨素材管理，只处理单个主视频和少量附加音频/字幕文件。
- 第一阶段不依赖云端服务。Edge-TTS 仍可作为可选配音能力。
- 不继续增加大量独立 BAT 脚本作为主要入口。BAT 可以保留为兼容入口。

## 当前项目适配结论

推荐在现有 `Script Studio` 项目里扩展，而不是另起完全独立项目。

原因：

- 现有项目已经有 Node.js/Express 服务、静态前端、WebSocket 日志、脚本运行和停止能力。
- `config/scripts.json` 已经存在 `视频处理` 分组，说明用户入口已经集中在这个工具面板。
- 复杂脚本已经开始从 BAT 迁移到 PowerShell 参数化脚本，适合作为后端能力来源。
- 如果重新做一个单独应用，会重复实现本地服务、日志、进程管理、配置保存等基础能力。

推荐目标形态：在 `Script Studio` 内新增一个独立的“视频工坊”视图，并保留原脚本列表作为通用工具入口。

## 方案比较

### 方案 A：继续增加 BAT/PS1 菜单

做法：把更多 ffmpeg 操作写成新的 BAT/PS1，例如音色调整、降噪、裁剪、合并等。

优点：

- 实现最快。
- 不需要改前端和服务端。
- 每个脚本可独立运行。

缺点：

- 工具会继续变多，杂乱问题加重。
- 参数不能组合，多个处理步骤会反复转码。
- 难以预览命令、保存预设、显示任务进度。

结论：不推荐作为主路线，只适合临时补充少数专业操作。

### 方案 B：复用 Script Studio，新增视频工坊

做法：保留现有脚本管理能力，在同一个本地 Web 应用里增加视频处理页面。后端新增视频探测、任务生成、任务运行 API。前端提供拖拽文件、参数面板、命令预览、任务日志。

优点：

- 复用现有项目基础设施。
- 用户仍从一个工具入口进入。
- 可以把分散脚本整理成统一能力模型。
- 后续可以逐步把旧脚本迁移成参数化任务。

缺点：

- 需要改 `server.js`、`public/app.js`、`public/index.html`、`public/style.css` 等核心文件。
- 需要设计一层 ffmpeg 参数模型，不能只拼接字符串。

结论：推荐。

### 方案 C：单独做 Electron/Tauri 桌面应用

做法：创建独立桌面应用，提供更完整的本地视频工具体验。

优点：

- 桌面体验更完整，拖拽、文件选择、通知、系统 ffmpeg 检测更自然。
- 与通用脚本管理解耦。

缺点：

- 项目成本更高。
- 会重复实现当前已有的运行、日志、配置、打包逻辑。
- 当前需求阶段不需要这么重。

结论：暂不推荐。等视频工坊稳定后，如果需要分发给别人使用，再考虑桌面壳。

## 推荐架构

### 前端

新增一个“视频工坊”工作区，布局建议：

- 左侧：输入区和媒体信息。
  - 拖拽上传区域。
  - 最近处理文件。
  - 视频基础信息：时长、分辨率、帧率、码率、编码器、音轨、字幕轨。
- 中间：参数面板。
  - 基础导出。
  - 画面处理。
  - 音频处理。
  - 字幕处理。
  - 配音与旁白。
  - 高级 ffmpeg。
- 右侧：任务与输出。
  - 命令预览。
  - 输出路径。
  - 开始、停止、打开输出目录。
  - 进度条、日志、历史任务。

UI 应该是工具型界面，不做营销页，不做大面积装饰。重点是密集但清晰，参数可以扫描，危险操作明确提示。

### 后端

新增视频工坊相关 API：

- `POST /api/video/probe`：调用 `ffprobe` 读取媒体信息。
- `POST /api/video/preview-command`：根据参数模型生成 ffmpeg 命令预览，不运行。
- `POST /api/video/jobs`：创建并启动视频处理任务。
- `GET /api/video/jobs/:id`：读取任务状态。
- `POST /api/video/jobs/:id/stop`：停止任务。
- `POST /api/video/presets`：保存参数预设。
- `GET /api/video/presets`：读取参数预设。

任务运行继续使用 Node 子进程和 WebSocket 输出，但不要直接复用交互式 BAT。新任务应使用参数化 ffmpeg 命令，避免 stdin 菜单输入。

### 配置与数据

新增配置文件建议：

- `config/video-workbench.presets.json`：用户预设。
- `config/video-workbench.history.json`：最近任务历史，保留最近 50 条。

输出目录建议：

- 默认：源文件同目录，文件名加安全后缀。
- 可选：`D:\code\myweb\daily\output\video-workbench`。

## 功能模块

### 1. 文件输入与探测

能力：

- 拖拽视频文件进入页面。
- 支持手动选择文件路径。
- 使用 `ffprobe` 读取媒体信息。
- 检测 `ffmpeg`、`ffprobe` 是否在 PATH。
- 中文路径必须正常处理，命令执行使用参数数组而不是拼接整条命令字符串。

### 2. 基础导出

能力：

- 输出格式：mp4、mkv、mov、webm、gif、mp3、wav、flac、aac。
- 编码器预设：H.264、H.265、VP9、仅复制流。
- 质量参数：CRF、preset、视频码率、音频码率。
- 快速启动：`-movflags +faststart`。
- 覆盖策略：默认不覆盖，支持手动确认覆盖。

### 3. 画面处理

从现有脚本迁移：

- 分辨率：原始、720p、1080p、2K、4K、自定义宽高、保持比例。
- 帧率：保持原始、24、25、30、60、自定义。
- 码率：视频码率、音频码率。
- 时间范围：开始时间、结束时间。
- 倍速：按速度倍率或目标时长导出。

后续扩展：

- 裁剪画面。
- 旋转和翻转。
- 补黑边或裁切适配竖屏/横屏。
- 水印添加和水印遮盖。
- 去黑边。

### 4. 音频处理

从现有脚本迁移：

- 提取音频。
- 音量倍数。
- 音频变速。
- 音频格式转换。

新增更精细能力：

- 响度标准化：`loudnorm`，让不同视频音量更一致。
- 降噪：`afftdn` 或 `arnndn`，第一阶段先做 `afftdn`。
- 均衡器：低频、中频、高频三段 EQ。
- 压缩器：`acompressor`，减少忽大忽小。
- 限幅器：`alimiter`，避免爆音。
- 淡入淡出：`afade`。
- 声道处理：单声道、立体声、左右声道互换。
- 音调/音色：
  - 基础模式：使用 `asetrate + aresample + atempo` 做音高变化。
  - 高级模式：如果本机 ffmpeg 支持 `rubberband` filter，则使用 `rubberband=pitch=...` 获得更自然的变调。

音色 UI 不应直接暴露一堆滤镜字符串，建议提供：

- 音高：低沉 / 原声 / 明亮，或半音滑杆。
- 语速：0.5x 到 2.0x。
- 低频增强：开关或滑杆。
- 人声清晰度：开关或滑杆。
- 背景噪声抑制：关 / 轻 / 中 / 强。

### 5. 字幕处理

从现有脚本迁移：

- 移除软字幕。
- 按语言移除指定字幕轨。
- 裁剪硬字幕区域。
- delogo 模糊遮盖硬字幕区域。
- 无字幕、软字幕、硬字幕三种输出模式。

新增能力：

- 外挂 SRT/ASS 文件合入视频。
- 字幕烧录样式预设。
- 字幕区域可视化输入：x、y、w、h。

第一阶段可以先做数值输入，后续再做画面预览框拖拽选择区域。

### 6. AI 配音与旁白

从 `video_dubbing.ps1` 迁移：

- Edge-TTS 依赖检测。
- 语言选择。
- 声音选择。
- 语速设置。
- 分段输入：开始时间、结束时间、文本。
- 可选字幕模式：soft、hard、none。
- 合成音频并与原视频混合。

改进目标：

- 分段表格替代 `start>end>text` 手写输入。
- 支持导入 CSV/SRT 作为分段初稿。
- 支持试听单段 TTS。
- 支持每段单独选择声音和语速。

### 7. 流水线与命令生成

所有功能最终生成一个 `VideoJob`：

```json
{
  "inputPath": "D:\\videos\\input.mp4",
  "outputPath": "D:\\videos\\input_processed.mp4",
  "format": "mp4",
  "video": {
    "resize": "1920x1080",
    "fps": 30,
    "crf": 23,
    "preset": "medium",
    "speed": 1.0
  },
  "audio": {
    "volume": 1.0,
    "loudnorm": true,
    "denoise": "light",
    "pitchSemitones": 0
  },
  "subtitle": {
    "mode": "keep"
  }
}
```

后端负责把 `VideoJob` 编译成 ffmpeg 参数数组。规则：

- 不使用字符串拼接执行命令。
- 每个滤镜由独立函数生成。
- 先做参数校验，再生成命令。
- 命令预览只用于展示，实际执行使用参数数组。
- 默认每个任务只转码一次，避免多个脚本串联导致画质损失。

## UI 交互原则

- 先让用户选文件，再展示可用参数。
- 参数按“常用优先，高级折叠”组织。
- 每个模块都有“启用”开关，未启用的模块不影响命令。
- 滑杆适合音量、音高、锐化、降噪强度。
- 分段配音使用表格，避免命令行文本格式。
- 输出路径明确显示，默认不覆盖。
- 运行前显示摘要：输入、输出、将执行的主要处理。
- 运行中允许停止，并保留日志。

- ffprobe JSON 解析。

## 迁移顺序

### 阶段 1：MVP

- 新增视频工坊页面入口。
- 实现文件拖拽和 ffprobe 探测。
- 实现基础导出、分辨率、帧率、码率、时间范围、倍速。
- 实现命令预览和任务运行。
- 保留现有 BAT 脚本不删。

### 阶段 2：音频增强

- 迁移音频抽取、音量、格式转换。
- 新增响度标准化、降噪、EQ、压缩器、限幅器、音高调整。
- 检测 `rubberband` filter 是否可用，作为高级音高模式。

### 阶段 3：字幕与配音

- 迁移软字幕移除、裁剪、delogo。
- 迁移 Edge-TTS 配音为表格化 UI。
- 支持导入/导出 SRT。

### 阶段 4：预设和历史

- 保存常用处理预设。
- 保存最近任务历史。
- 支持复制命令、打开输出目录、重跑任务。

## 风险与处理

- ffmpeg filter 可用性差异：启动时检测 filter 列表，高级能力不可用时禁用对应控件。
- 中文路径和空格路径：后端执行必须使用参数数组，禁止拼接命令字符串执行。
- 多滤镜组合复杂：建立过滤器构建器，先支持常用组合，再扩展复杂场景。
- 大视频处理耗时长：显示进度、允许停止、保留日志。
- 现有脚本质量不一致：不直接把 BAT 菜单搬进 UI，而是提取可靠命令逻辑。

## 待确认决策

1. 视频工坊是否作为 `Script Studio` 内置页面实现，而不是新建独立桌面应用。
2. 默认输出目录使用源文件同目录，还是统一放到 `output/video-workbench`。
3. 第一阶段是否只支持单视频输入。
4. 音色调整里是否优先做“简单模式”，高级 ffmpeg filter 放到折叠区域。
5. 是否需要保留现有 `视频处理` 分组脚本作为兼容入口。

## 推荐结论

建议采用方案 B：在现有 `Script Studio` 中新增“视频工坊”。第一阶段先把分散的视频处理脚本收敛成统一 UI 和任务模型，不急着做完整剪辑器。核心价值是把“多个 BAT 菜单”升级为“一个参数化视频处理流水线”，让拖入视频、调整参数、生成最终视频成为主流程。
